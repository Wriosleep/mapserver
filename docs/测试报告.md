## 四、核心验证项

### 1. 翻转正确性(全量)

项目自带的 `verify_flip()` 只抽查 z=1 的两张瓦片。本次把判据扩展到**全部 1365 张**:

```
对每个 (z, x, y):  MD5(tiles_tms/z/x/(2^z-1-y)) == MD5(tiles_xyz/z/x/y)
```

结果:**1365/1365 全部一致**,且列号目录未被改动(仅 Y 轴翻转)。
覆盖度由 2 张提升至 1365 张,提升 682 倍。

### 2. 投影函数

`gen_source.py` 的墨卡托投影经往返测试:`lat → px → lat` 在全纬度范围(含南半球悉尼 -33.87°)误差 < 0.01°。
`lat_to_px(±90)` 被正确截断到 ±85.05112878,未产生 inf/nan。

### 3. 幂等性

重跑 `convert_tiles.py` 全量复算,产物与现有 `tiles_tms` **逐张 MD5 一致**,确认转换是确定性操作。

## 五、缺陷汇总

| 编号 | 位置 | 描述 | 严重度 | 状态 |
|:-:|---|---|:-:|:-:|
| **D-01** | `download_tiles.py::fetch_one()` | 断点续传判据为「文件存在且字节数 > 0」,不校验内容。下载失败时服务端返回 200 + HTML 错误页也会被当成已完成,此后永久跳过。**一次网络抖动即可往数据集里埋入假数据,且全程不报错** | 高 | ⚠️ 确认 |
| **D-06** | `README.md` 1.4.1 / `download_tiles.py` | 文档实测记录「24 线程」,脚本 `--workers` 默认值为 8。按文档复现得不到相同性能数据 | 低 | ⚠️ 确认 |
| D-02 | `download_tiles.py` | 未校验 PNG 魔数(与 D-01 同源) | 中 | 待固定 |
| D-04 | `convert_tiles.py` | `--clean` 直接 `rmtree`,破坏性操作无二次确认 | 中 | 待固定 |
| D-05 | `slice_tiles.py` | 假设源图为正方形,非方形源图静默变形 | 低 | 待固定 |
| D-07 | Apache 配置 | 无 `Cache-Control` / `Expires`,瓦片被反复全量请求 | 中 | 待固定 |

### D-01 复现路径

```bash
# 1. 造一个「非空但不是 PNG」的假瓦片(模拟下载到错误页)
echo "<html>403 Forbidden</html>" > tiles_xyz/0/0/0.png

# 2. 重跑下载脚本 —— 该文件不会被重下,也不会报错
python download_tiles.py --max 0
# 输出: 跳过 1 张
```

### D-01 修复建议

在 `fetch_one()` 的跳过分支中加入内容校验:

```python
PNG_MAGIC = b"\x89PNG\r\n\x1a\n"

if os.path.exists(path) and os.path.getsize(path) > 0:
    with open(path, "rb") as f:
        if f.read(8) == PNG_MAGIC:      # 只有确认是 PNG 才跳过
            return "skip"
    # 否则落到下面重新下载
```

修复后 `tests/test_defects.py::test_d01_*` 会从 xfail 转为 XPASS,摘掉标记即为验收通过。

## 七、结论与建议

**结论:** 本地数据链路(下载 → 切片 → 翻转)质量良好,55 条本地用例全部通过;
翻转正确性经全量 1365 张验证,可确认无隐患。接口与性能层因环境未就绪尚未回归。

**建议(按优先级):**

1. **启动虚拟机跑一遍接口层** —— 16 条用例已就绪,只需 `TILE_BASE_URL` 指向即可。**这是投入产出比最高的一项:用例写好了,唯一卡点是环境。**
2. **修复 D-01**(高)—— 补 PNG 魔数校验,避免假数据静默污染数据集;修好后 `test_d01_*` 会自动转 XPASS,摘掉标记即完成闭环;
3. **补齐 L4 性能基线** —— 用 `ab` 建立 httpd 的 QPS 曲线,再与 nginx 对比(README 2.3 的空白区);
4. ~~接入 CI~~ —— **已完成**:`.github/workflows/tests.yml` 在 push / PR 时自动跑 L0 + L1,并把 Allure 报告作为 artifact 上传(见下节);
5. 修复 D-02 / D-04 / D-05 / D-07 并同步到缺陷回归集。
