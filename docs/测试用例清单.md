## L1 · 集成测试(磁盘产物契约)

对应文件:`tests/test_integration.py`　　执行方式:`pytest tests/test_integration.py`

| 编号 | 测试点 | 用例要点 | 预期结果 | 状态 |
|:-:|---|---|---|:-:|
| I-01 | 目录完整性 | `tiles_xyz`、`tiles_tms` 逐级统计 | 每级 4^z 张,级别连续 z0~z5,合计 1365 | ✅ |
| I-02 | 命名契约 | 遍历全部文件名 | 严格 `{z}/{x}/{y}.png`,x/y ∈ `[0,2^z-1]` | ✅ |
| **I-03** | **全量交叉比对** | 1365 张逐张 MD5:`tms/z/x/y` vs `xyz/z/x/(2^z-1-y)` | 全部一致 | ✅ |
| I-04 | 仅 Y 轴翻转 | 比对 z 级下的列目录集合 | x 列完全保留,防「整体反转」假成功 | ✅ |
| I-05 | 幂等性 | 重跑 `convert_tiles.py` 全量复算 | 产物 MD5 逐张一致 | ✅ |
| I-06 | `--clean` 清理 | 预置脏目录后带 `--clean` 运行 | 旧产物被清除,无残留 | ✅ |
| I-07 | 源缺失暴露(负向) | z=1 只放 3/4 张 | 计数如实回 3,不被掩盖 | ✅ |
| I-08 | JPG 转换产物 | `--dst-fmt jpg` | 可解码、尺寸不变、无 0 字节 | ✅ |
| I-09 | RGBA→JPG | 透明通道源图 | 不抛异常,正确剥离 alpha | ✅ |
| I-10 | 文档数量一致 | README 声称 1365 张 vs 实际文件数 | 吻合 | ✅ |

> **I-03 是这一层的核心。** 项目自带的 `verify_flip()` 只抽查 z=1 的两张瓦片;
> 本用例把同样的判据扩展到全量 1365 张 —— 这是一次实打实的覆盖度提升。

## 缺陷清单

对应文件:`tests/test_defects.py`(以 xfail 固定,修复后自动转 XPASS 提示摘标记)

| 编号 | 位置 | 缺陷描述 | 严重度 | 状态 |
|:-:|---|---|:-:|:-:|
| **D-01** | `download_tiles.py` `fetch_one()` | 断点续传只判「文件非空」,不校验内容。服务端返回 200 + HTML 错误页时会被当成已完成,此后永久跳过重下 —— 一次网络抖动即可往数据集里埋假数据且不报错 | 高 | ⚠️ 确认 |
| **D-06** | `README.md` 1.4.1 vs `download_tiles.py` | 文档实测标注「24 线程」,脚本 `--workers` 默认值为 8;照文档复现得不到相同性能数据 | 低 | ⚠️ 确认 |
| D-02 | `download_tiles.py` | 下载后未校验 PNG 魔数(与 D-01 同源) | 中 | ⏳ 待固定 |
| D-04 | `convert_tiles.py` | `--clean` 直接 `rmtree`,破坏性操作无二次确认 | 中 | ⏳ 待固定 |
| D-05 | `slice_tiles.py` | 假设源图为正方形(`resize((side, side))`),非方形源图会静默变形 | 低 | ⏳ 待固定 |
| D-07 | Apache 配置 | 无 `Cache-Control` / `Expires`,瓦片被反复全量请求 | 中 | ⏳ 待固定 |

## 复现方式

```bash
cd E:/2026/mapserver
pip install -r requirements.txt

# 全部(接口部分在服务器不可达时自动 skip)
python -m pytest

# 只看本地链路(不依赖虚拟机)
python -m pytest tests/test_unit.py tests/test_integration.py

# 指定服务器地址
TILE_BASE_URL=http://192.168.247.129/tiles python -m pytest tests/test_api.py

# 跨机一致性(A-13 需要第二个入口)
TILE_BASE_URL=http://192.168.247.129/tiles \
TILE_BASE_URL_ALT=http://127.0.0.1/tiles python -m pytest tests/test_api.py

# 含较慢的复算用例
python -m pytest -m slow

# Allure 报告
python -m pytest --alluredir=allure-results
allure generate allure-results -o allure-report --clean
```

> Windows 控制台若出现中文乱码,前置 `PYTHONIOENCODING=utf-8` 即可(conftest 已尝试自动切换)。
>
> **执行项 vs 测试点**:`pytest` 报出的 73 是参数化展开后的执行项。清单里的 U-01~U-10b、I-01~I-10、A-01~A-13 是**测试点**,一个测试点挂多个参数就算多条,例如 A-10(路径穿越)一个点展开成 4 条。
>
> **CI**:`.github/workflows/tests.yml` 在 push / PR 时自动执行 L0 + L1(接口层在公开 runner 上恒为 skip),Allure 报告作为 artifact 上传。
